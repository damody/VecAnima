# 開發錯誤與防止重犯

每次記錄：觸發條件、原因、通用修正、驗證與狀態。不得只記錄錯誤訊息而沒有後續處置。

## E001：Windows extended path 導致 FFmpeg concat 相對資產解析失敗

- 觸發：Rust canonicalize 產生 `\\?\E:\...\preview.ffconcat`。
- 原因：FFmpeg concat demuxer 無法以該前綴正確解析相對路徑。
- 修正：對 FFmpeg 輸入正規化 drive／UNC 前綴與分隔符；不更動實際檔案、不改工作目錄作補丁。
- 防止重犯：`concat_paths_strip_extended_windows_prefix` 單元測試，以及含空格、單引號、中文的端到端測試。
- 狀態：已修正。失敗資料在 `output/rust-isekai-20s/` 標示 incomplete，成功資料在 `output/rust-isekai-20s-v2/`。

## E002：OpenCV Windows imread 無法可靠讀取中文路徑

- 原因：原生窄字元檔案 API 與 UTF-8 路徑不相容。
- 修正：Rust std::fs 負責 Unicode 檔案操作，OpenCV imdecode／imencode 處理記憶體；PNG 寫出由 Rust 執行。
- 防止重犯：端到端測試輸出 `Rust's 輸出` 目錄，實際驗證 SVG 渲染及 MP4。
- 狀態：已修正。

## E010：複雜畫面中的筆觸候選造成錯誤補色與過度分段

- 觸發：Isekai 角色影格；合成簡單線通過但實際畫面邊界受到破壞，短曲線數量異常偏高。
- 原因分析：剖面越過更深色特徵、推估節點跨越原圖色差、色彩分段重複使用不相容顏色的共同端點，且所有 ribbon 覆蓋像素都被當成有效筆觸。
- 修正方向：剖面必須停留於同一亮度谷；推估須符合原圖顏色；色彩斷點真正分開；可見性納入原圖顏色誤差上限，不合格像素由色塊模型表達。
- 狀態：修正與功能檢查中。不接受只在簡單合成素材通過。

## E003：手動 SVG 逐幀被影片 seeked 事件重設

- 原因：瀏覽器影片 seek 精度與手動 SVG 時間軸不同；seeked 再同步回較早時間。
- 修正：明確區分手動逐幀、SVG 播放與影片同步三種控制狀態；手動模式不接受影片時間覆寫。
- 防止重犯：瀏覽器確認下一幀維持 2/120、0.042 秒，縮放不改索引。
- 狀態：已修正。

## E004：OpenCV 最小模組使用 opencv_world 的 CMake 組合錯誤

- 原因：4.14.0 world 聚合在排除 highgui 的最小設定仍呼叫其配置函式。
- 修正：使用上游支援的各模組 DLL／LIB，Rust 明確連結 core、imgproc、imgcodecs；未改上游原始碼。
- 防止重犯：安裝腳本固定最小模組清單；doctor 真正呼叫色彩轉換。
- 狀態：已修正。

## E005：FFmpeg 合成素材時間參數缺少整數部分

- 觸發：直接傳入 `-t .2`，FFmpeg 9.0.2 拒絕。
- 修正：工具產生參數使用標準數值格式，例如 `0.2`；CLI 接收值後以數值轉字串。
- 狀態：已修正。

## E006：PowerShell 包裝腳本對 clippy 的雙連字號傳遞

- 觸發：包裝腳本傳遞 `-- -D warnings`，clippy 最終收到缺少分隔符的 cargo check 參數。
- 修正：包裝腳本使用明確 `CargoArguments` 字串陣列介面。需要保留分隔符時，呼叫 `-CargoArguments @('clippy', '--locked', '--offline', '--all-targets', '--', '-D', 'warnings')`，不猜測或重寫編譯器旗標。
- 驗證：上述嚴格 Clippy 指令實際通過，雙連字號作為陣列資料原樣傳入；一般 cargo 操作仍可使用剩餘參數。
- 狀態：已修正。

## E007：清理非必要舊版下載暫存遭自動審查拒絕

- 動作：遞迴移除 `.tools/opencv-4.13.0-parts`；審查只提供政策限制。
- 處理：保留暫存，不重試變形刪除指令，不影響鎖定 4.14.0。
- 狀態：保留，不作為開發阻塞。

## E008：剖面不可信區段不可跳過後直接接線

- 發現：筆觸初版跳過過遠的不可信取樣點後，剩餘點可能被跨越缺口連接，且節點索引可能與樣本索引錯位。
- 修正：保留 Option 樣本序列，遇到不可信段就分段；僅在鄰近已量測節點 3 像素內允許明確標示 inferred 的端點／交叉點寬度。節點 ID 按原始 path 索引取值。
- 狀態：已修正，持續加入功能檢查。

## E009：正式筆觸重建未保留單像素深色線

- 觸發：合成色塊內一像素線，profile 模式渲染為背景色而非深色。
- 發現方式：既有原生 CLI 孔洞／細線端到端檢查。
- 原因：寬色帶也可能符合局部剖面；多條不同顏色 ribbon 重疊時，單純按偵測順序畫出會讓淺色 ribbon 覆蓋真實深色線。此外剖面搜尋越過第一個背景平台，可能把遠方另一條邊界當成線寬。
- 修正：第一個梯度恢復平台即終止剖面；重疊 ribbon 依原圖顏色誤差求局部可見性分區，儲存純向量 occlusion clip，支援同一對曲線在不同位置改變遮擋順序。沒有硬編碼深色優先或素材座標。
- 驗證：原有孔洞／單像素線／重現性端到端檢查通過，未放寬門檻。
- 狀態：已修正。

## E011：交叉約束測試未提供交點

10×10 整數格點的兩條對角線交於 (4.5,4.5)，測試未提供該頂點，與 PSLG 契約矛盾。改用 9×9 格點，其交點 (4,4) 已存在；保留缺少交點必須拒絕的測試。15 個 Rust 功能測試通過，沒有吞掉約束。狀態：已修正。

## E012：Windows Python 預設文字編碼

以預設 cp950 讀取 UTF-8 中文 Markdown 時失敗。工具腳本一律明確指定 encoding='utf-8'，或使用 python -X utf8。未將失敗操作視為成功。狀態：已修正。

## E013：約束邊走訪可能返回進入邊

檢查任意方向約束走訪時發現，同一三角形有進出兩條相交邊，不能只取第一條。修正為排除已走訪鄰接面，並加入 16 組確定性亂數點集、非格線約束及插點檢查。另先驗證新增點位於域內再變更頂點陣列，避免失敗留下不完整狀態。18 個 Rust 功能測試通過。狀態：已修正。

## E014：快取 JSON 浮點解析未保證逐位元往返

實際續跑的品質指標相同，但 SVG bytes 改變。幾何細化／曲線擬合對浮點分支敏感，serde_json 預設快速解析並不保證 f64 每個位元往返一致。啟用 float_roundtrip；快取重新產生後以 SHA256 比較 SVG、原生 JSON 與 PNG，不能只比較 PSNR。狀態：已修正；原生 CLI 的快取／續跑端到端測試以 SVG、JSON、PNG SHA256 一致通過。

## E015：新模組整合時漏傳參數及缺少型別

網格邊界對比參數加入後，編譯檢查發現呼叫點漏傳 palette、閉包索引型別未指定。已補齊所有呼叫點與 usize 型別；Rust 21 個功能測試通過。新增資料契約時先編譯呼叫鏈，避免拖到端到端檢查。狀態：已修正。

## E016：同一 apply_patch 對同一檔案同時刪除及新增

工具拒絕對 viewer.html 的複合更新，未寫入。改以單次 UTF-8 檔案寫入完成整檔替換。狀態：已修正。

## E017：瀏覽器舊 tab binding 已失效

沿用先前 turn 的 tab 2 時瀏覽器回報不屬於目前 session。重新建立同一 IAB 的功能檢查頁，未重選其他瀏覽器。狀態：已恢復。

## E018：播放器選單的 label locator 未匹配

可及性樹將原生 select 顯示為 popup button，精確 label「顯示」的 locator 未匹配。依已觀察到的 ID mode 定位 select，完成 SVG 圖層切換檢查，沒有盲目重複操作。狀態：已修正。

## E019：把像素邊界與平均筆觸色當成正式向量模型

使用者目視發現線條與色塊仍呈格狀。原因：局部角度擬合把數位階梯視為真實尖角、可見性裁切沿像素格、色塊硬約束保留大量格邊；雖保存各節點顏色，實際 ribbon 卻用整條平均色。這是模型與重建未閉環，不是調高解析度可以修復。

修正：多尺度尖角／平滑曲線、連續左右線寬與線性光顏色、共用平滑色塊邊界，且所有正式欄位實際參與重建。加入可變色／線寬及放大外觀的檢查，不以 PSNR 單獨判定成功。狀態：連續模型與渲染已接通，合成／Isekai 當前功能檢查通過；完整專案驗收另列。

## E020：平滑邊界誤差帶過度排除一般漸層

漸層 CLI 測試發現最大色差 9 超過設定 8。量化分區不一定是真正顏色不連續，不能把每條分區界線附近都排除細化。改為檢查法線兩側原圖色差，只有實際強不連續的移動邊界才分開報告；一般漸層維持完整誤差細化。

## E021：SVG 三角形抗鋸齒造成內部透明裂縫

直接拿掉 crispEdges 會讓相鄰三角形各自混合 alpha，產生背景裂縫。改為連通網格扇區共用抗鋸齒外輪廓裁切、內部不透明色彩拼片，並在裁切外延伸邊界色以覆蓋邊緣部分像素。筆觸使用平滑 Bézier 輪廓裁切。

## E022：超取樣共享邊重複累計

三角形走訪包含共同邊，四個子像素可能被兩個面重複計算；不能用累計次數判斷覆蓋。改為每個子像素一次明確歸屬，再以線性光積分；完整檢查所有子像素覆蓋。

## E023：擬合樣本誤差不足以保證曲線拓撲

Isekai 密集交界發現曲線 4135 重試仍交叉。控制點可以在樣本之間越界，只縮小擬合誤差沒有保證。局部重試同步縮小平滑位移與三次插值控制柄的可達範圍，保留共享切線，直到非交叉；曲線展平／加密的終點直接保留原端點，避免浮點重算造成共享節點微縫。Isekai 功能檢查與密集四色情況通過。

## E024：來源色差被誤用為遮擋，且相似筆觸互相裁碎

抗鋸齒的邊緣像素與中心色自然不同，不能據此刪掉沒有其他筆觸遮擋的幾何。改為完整 ribbon 參與所有權判定，僅真正重疊且來源擬合殘差相差超過設定色差時分割；同色微小數值差不會互相裁碎。裁切外形使用平滑曲線。斜線連續性回歸通過。

## E025：暗側色帶骨架及短粗陰影誤作筆觸

二值局部對比色帶直接細化，中心可能落在色塊暗側；且短粗陰影容易形成不合適的圓端帽。改為多尺度 f64 Gaussian Hessian 亮度谷中心檢測，法線剖面驗證後才建骨架。以可設定 --stroke-min-aspect（預設 3，中心線長／90 百分位總線寬）讓緊湊色谷留在填色模型。避免把單張素材座標、顏色或角色規則寫入演算法。

## E026：嚴格 Clippy 發現新整合程式風格問題

新渲染與共享圖模組有 needless_range_loop、collapsible_if、write_with_newline、manual_is_multiple_of。已依迭代器及標準 API 修正，all-targets -D warnings 通過。

## E027：骨架在每個 junction 停止、節點色差再次切碎線條

放大檢查仍看到長筆觸分成短段。原圖骨架在每個三叉／四叉節點停止，加上色差切段，令方向連續的長線被丟棄。改為多節點切線方向配對半邊，各條邊走訪一次；色彩作為連續通道，不再以相鄰顏色差直接斷線。只對無剖面證據的缺口斷開，低信心不跨越長空段。顏色取樣改用次像素位置的線性光雙線性插值，避免最近像素顏色跳動。形狀檢查使用 90 百分位線寬，單一 junction 線寬離群值不會刪掉整條線。

## E028：瀏覽器縮放中立即點擊 checkbox 未改變狀態

縮放造成佈局更新，立即 uncheck 的首次動作未生效。已先重新讀 DOM 確認 checked，再以同一已知 label 重試並驗證；沒有把失敗操作當作成功。另將縮放的對照中心統一以原圖為準，原圖 display:block，避免對照兩側焦點漂移。

## E029：剖面已恢復背景後遇到較暗鄰線仍整段拒絕

眼瞼／虹膜等相鄰深色特徵，法線剖面跨過第一條線恢復背景後又遇到更暗的鄰線，舊分支直接 return None，導致漏線。改成已取得足夠恢復對比時終止搜尋並保留第一個半高交點；尚未恢復才拒絕。新增相鄰兩條不同深度細線的剖面回歸通過，未跨過鄰線計算錯誤線寬。

## E030：Windows 播放器服務鎖住 Release 可執行檔

新建置嘗試替換正在執行 serve 的 target/release/vecanima.exe，Windows 回報存取被拒。以 PID 與完整 command line 確認是本輪啟動的 51284 本地唯讀服務後，只停止該程序再建置。未把舊 binary 的測試結果算成新程式驗證；新建置後重新執行驗證。後續需先完成建置才啟動服務，或使用獨立版本快照提供服務。

## E031：三色交界固定格點使色塊仍呈階梯

SVG 放大檢查發現，即使界面內部用曲線，密集 palette junction 仍固定每個整數格角，短界面無法平滑。增加全圖共享頂點的帶位置錨定 Laplacian 次像素鬆弛，最大位移 0.45 工作像素，圖框固定，所有入射曲線共用位置；曲線建構後仍做交叉與孔洞檢查。密集四色回歸通過，不只改顯示抗鋸齒。

## E032：大型 SVG 首次解析阻塞播放器互動

最新約 30 MB／幀的 SVG 初次解析時，切下一幀的瀏覽器點擊逾時。先讀回實際狀態再操作，不重複盲點。記錄為 SVG 匯出資料量／互動效能限制；正式原生模式使用 GPU 緩衝，不需下載整個 fills SVG。尚需後續 SVG 編碼成本優化，未宣稱播放效能已驗收。

## E033：筆觸漏辨識及抗鋸齒殘邊污染填色 SVG

使用者關閉筆觸後仍見深色細線。Gaussian 背景估計在不同底色兩側不對稱，且先挑獨立 Hessian ridge 再細化會打斷線的連通性；只移除已擬合 ribbon 的覆蓋像素也留下抗鋸齒殘邊。先前測試未直接檢查填色 SVG 的分層結果。

修正：以形態學 closing 的 black-hat 殘差估計細線，連通支撐先細化，再以多尺度導數修正中心／法線；剖面量測殘差，節點顏色仍取來源 RGB。填色移除遮罩包含已重建筆觸附近、具有來源殘差證據的弱邊緣，避免直接刪除所有深色。新增實際渲染 Flat／Mesh 填色 SVG 的測試，涵蓋跨兩種底色、沿底色交界的線條以及應保留的深色矩形。Isekai 新輸出已重算，舊輸出不會自動更新。

## E034：closing 核半徑誤設為最大線寬

初版半徑直接使用 stroke_max_width，核直徑約為兩倍最大線寬，會將整個較窄色塊判作筆觸，造成原生追蹤測試沒有預期對應。修正半徑為 ceil(stroke_max_width / 2)，核直徑約最大線寬加一；原生 CLI 追蹤及其餘回歸重新通過。

## E035：OpenCV 測試 Mat 借用暫時陣列

新增色盤測試以 Mat::from_slice 借用即時陣列，Rust 回報 E0716。改用具名 palette_bytes，使底層資料活至 Mat 使用完畢，未繞過生命週期檢查。

## E036：以中心線長度判斷形狀會漏掉短細筆畫

新增短細線／深色圓盤回歸時，即使 aspect 降為 2，細化縮短端點後的中心線仍被拒絕。形狀比改用 (中心線長度 + 90 百分位總線寬) / 總線寬，納入圓端帽的近似延伸；預設為 2。短細筆畫可進入筆觸層，緊湊深色圓盤仍留在填色層。已移除臨時診斷輸出，更新 CLI 說明，34 個 Rust 測試與 26 個 Python 測試通過。

## E037：半高寬移除及近鄰複製留下不明陰影

使用者放大圖證實 E033 的修正仍不充分。筆觸幾何半高寬不是完整來源污染範圍；附近未遮罩的像素也可能是抗鋸齒／混色殘邊。把它當底色複製，會擴大成色塊層的暗斑。修正分開保存 support_left／support_right 的約 98% 剖面恢復範圍，重建完整界面安全帶，排除孤立混色 donor，並在最大線寬尺度內補齊連通的不穩定殘邊。穩定色彩核心阻止擴散。新增寬 Gaussian 淡邊、孤立混色被複製及相連殘線的回歸，直接驗證填色 SVG，不能只檢查 checkbox 的狀態。

## E038：AI 邊界安全帶可能吞掉真正的窄陰影

中間版本完整清除殘邊，但單純擴大未知區會使靠近界面的真實窄陰影失去 donor，第一場景 MAE 一度 3.36497。模型邊界不是筆觸真值。修正保留無筆觸所有權、模型低線條證據且原圖顏色一致的核心，再從乾淨核心恢復界面；窄真陰影新增回歸。最終第一場景 MAE 2.48428，第二場景 1.26846；數值及目視均保留在功能記錄，不把去殘影當作所有品質指標都改善，也不宣稱語意完美。

## E039：OpenCV 文件中的 ONNX API 名稱與實際生成綁定不同

查閱 vendor docs 得到 read_net_from_onnx_2_def，但針對本地 OpenCV 4.14.0 生成的是 read_net_from_onnx_buffer，編譯報 E0425。依實際生成綁定修正；新增 Frame 欄位的兩個測試初始化也補齊，E0063 解決。後續以本地生成 API 為準。

## E040：含錯誤上下文的多檔 patch 被整批拒絕

## E041：AI 模型與工具鏈的可重現性不能只記錄檔名

模型路徑未變而權重變更會讓快取混用。run.json、階段 key、模型網路快取及每幀 fill_recovery 都加入 SHA256；原生端到端測試實際修改模型內容並確認續跑拒絕。PyTorch 只負責轉換，正式 Rust 使用本地 OpenCV DNN；模型來源、授權、原始及 ONNX 雜湊、轉換程式、工具 wheel 與授權全部保存。ONNX legacy exporter 的棄用警告不是失敗；選 opset 13 是為了已驗證的原生匯入相容性。

## E042：官方 PyTorch download-r2 wheel 下載回報 403

封存腳本讀到官方 index 的 download-r2.pytorch.org 連結，但下載回報 403。改用同一官方 download.pytorch.org artifact 路徑，仍強制核對 index 提供的 SHA256，未改用未知鏡像或跳過校驗。wheel 已下載並保存到當前專案 third_party/wheels。

## E043：乾淨填色揭露筆觸斷點，不能只驗證關閉狀態

三倍放大重新開啟筆觸後，發現先前填色殘線曾掩蓋原生輪廓的短斷點。AI 只拿來篩選局部殘差，而拓撲仍由局部對比決定，低對比段會被切碎。不能將乾淨的 fills SVG 當作完整分解已完成。

修正：有模型時直接以學習到的連續線條支撐建立骨架拓撲；優先使用來源殘差剖面測量線寬，缺少有效剖面時，只有來源 RGB 確有局部邊界證據才使用模型剖面推估，標為 inferred 並降低 confidence。完全平色上的模型幻線拒絕。節點色仍從來源取樣，所有段仍重建為平滑可變寬曲線。新增強線—弱對比長段—強線必須保持同條連通筆觸，以及平色幻線必須拒絕的回歸。39 Rust／27 Python／嚴格 Clippy 通過，重新重算兩個場景並同時檢查筆觸開／關；最終輸出改為 output/clean-layers，先前 clean-fill-* 留作診斷歷史。

## E044：AI 色彩／柔光邊界被當成應移除的筆觸

額外檢查 40 秒處不同角色及柔光場景，發現直接把所有模型邊界擴為未知區會傷害真實陰影及漸層。修正：AI 邊界只提供拓撲與位置證據；移除範圍必須同時具有來源 black-hat 暗谷支撐。色彩核心亦接受跨 palette 分區但局部線性平滑的來源場，避免把量化界線當成陰影破碎原因。新增「AI 宣稱有邊界，但純漸層必須逐像素保留」回歸，40 Rust／27 Python／嚴格 Clippy 通過。三個來源區間作當前功能檢查，不據此宣稱任意動畫語意分解或全片品質已完美。

補充：推估筆觸的來源證據同時要求局部 RGB 範圍及二階差分，拒絕平色與線性漸層上的模型幻線。

## E045：來源剖面受相鄰陰影污染，線寬突變與法線抖動

實際三倍 SVG 合成檢查發現髮絲局部變粗及抖動，不能因僅填色乾淨就宣布完成。來源 black-hat 的背景回復可能包含相鄰陰影，Hessian 法線亦可能轉向旁邊區域，交替使用來源／模型中心造成抖動。

有模型時以連續路徑切線建立法線及一致中心；來源線寬受學習支撐的剖面與距離場約束，約束／推估標記 inferred 並降低 confidence。沿線先用局部中位數剔除孤立寬度峰值，再連續內插。完整淡邊移除支撐另存，不隨幾何縮窄而截斷。新增相鄰陰影不應膨脹線寬及單一污染剖面不應形成粗塊的回歸，41 Rust／27 Python／嚴格 Clippy 通過。最終輸出 output/verified-clean-layers 及 scene2／scene3，validated-layers、width-constrained 與 clean-fill-* 均是歷史實驗；保存實際 SVG 筆觸開／關畫面，並明列仍有低解析度與語意近似。

## E046：單門檻模型支撐及顏色拒絕切斷真實連續筆觸

獨立筆觸檢查仍有弱線斷點；模型支撐只用 0.2 單門檻會切掉連通弱段，而缺失剖面用鄰段顏色拒絕，錯把變色筆觸當成不相關線。改用強支撐錨點連接的弱支撐 hysteresis；來源暗谷即使只有 1–2 灰階也可支持模型剖面，平色／線性漸層仍拒絕。缺失剖面僅沿既有模型路徑、兩側有效錨點與來源暗谷插值線寬；顏色獨立從局部來源墨谷取樣，不複製鄰段顏色。回歸提高為來源對比 2、模型弱段 0.1 的長線仍須連通。

## E047：最近鄰 donor 與遠端色盤距離造成柔光階梯

即使 donor 乾淨，最近鄰顏色延伸仍會產生 Voronoi 色階；色盤中心距離亦不能證明界面是硬跳變。改為線性光 screened harmonic extension：乾淨 donor 為固定邊界，真實跨區顏色跳變設 no-flux，正 screen 保證孤立區可解；以預條件共軛梯度求解並保存迭代、殘差及收斂狀態。色盤只提供初始區域，硬 mesh 約束須有來源中央跳變集中、外側坡度較低的證據；連續 ramp 不被硬切，真實 cel-shadow 繼續保留。

新增實際恢復的漸層誤差不超過 1 灰階、硬陰影逐像素不滲色，以及遠端色盤中心差很大但來源 ramp 必須連續的回歸；43 Rust／嚴格 Clippy 通過。未以提高色盤數、縮小畫面或素材特判掩蓋。

## E048：fmt 後函式簽名上下文失效

## E054：形狀修正的 V1／V2 零碎分區及 SVG 節點爆增
